# Automated Legal Issue Extraction — validation code

This repository contains the code and annotation data used to produce the
validation results of the paper *Automated Legal Issue Extraction* (extraction
of IRAC-aligned legal issues from Italian tax-court judgments with DeepSeek V3,
validated against two tax-law experts).

All analysis code is contained in Jupyter notebooks. Each notebook is
self-contained, declares at the top which paper tables it produces, and labels
every printed table with the corresponding LaTeX table label of the paper
(e.g. `tab:issue_pairwise`).

## Data notes

- The two annotators are referred to as **A1** and **A2**, as in the paper.
- `validation_annotator_A*.csv` contain one row per LLM-extracted issue with
  the annotator's evaluation: presence of the issue in the judgment, missing
  issues, the annotator's own citation list and its overlap with the LLM's,
  binary scores on citation reasons, and 1–5 Likert scores on the free-text
  fields. Column headers are in Italian (the annotation language); the
  notebooks document the meaning of every column they use. These files contain
  the annotation of the LLM output **after** the hallucination filter.
- 50 test judgments in total: 20 annotated by both experts (used for
  inter-annotator agreement), 15 + 15 annotated by a single expert.
- The XMLs are the raw model outputs; party names are anonymized
  (`Ricorrente_1`, `Società_1`, ...). In `hallucination/references_test_set.csv`
  references are numbered consecutively across the issues of a judgment
  (D1...Dn per judgment), while the XMLs restart from D1 in each issue;
  notebook 05 matches them on the reference text.
- All citation-level analyses exclude the 4 LLM-extracted issues that the
  annotators marked as absent from the judgment (listed in notebooks 01
  and 05).

## Running

```bash
pip install -r requirements.txt
jupyter lab          # or jupyter notebook
```

The notebooks are independent of each other and can be run in any order
(each loads the data it needs from `data/`, and notebook 05 additionally
imports `src/principi_classifier.py`). Run each notebook top to bottom;
expected runtime is a few seconds per notebook. Notebook 05 (re)generates
`data/xml/extraction_run1_post_filter/`.

The only cross-notebook dependency is informational: the comparison table at
the end of notebook 04 (`tab:sens_comparison`) repeats, for context,
agreement values computed in notebooks 01 and 02; they are hard-coded there
with a comment pointing to their source.

The extraction pipeline in `pipeline/` is included for documentation and is
not needed to reproduce the validation results. Running it requires an LLM
API key (read from the `OPENROUTER_API_KEY` environment variable) and the
corpus paths referenced inside the notebook, which are local to the authors'
machine.
